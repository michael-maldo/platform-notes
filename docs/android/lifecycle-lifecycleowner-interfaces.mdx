# Android Lifecycle, LifecycleOwner interfaces

The `Lifecycle` and `LifecycleOwner` interfaces are part of the Android Architecture Components,
specifically designed to help manage the lifecycle of components such as `Activity`, `Fragment`, and
`Service`. These interfaces provide a standardized way to observe and interact with the lifecycle state
of these components.

### Lifecycle Interface

The `Lifecycle` interface represents the current state of a component and the events that occur as the
component's lifecycle progresses. It defines constants for different lifecycle states and provides
methods to observe lifecycle events.

Here are the key constants in the `Lifecycle.State` enum:

- **`INITIALIZED`**: The component has just been created.
- **`CREATED`**: The component has been created and is not yet visible to the user.
- **`STARTED`**: The component is visible to the user but not in the foreground.
- **`RESUMED`**: The component is visible to the user and in the foreground.
- **`DESTROYED`**: The component has been destroyed and is no longer in use.

The `Lifecycle` interface also provides methods to add and remove observers that will be notified of
lifecycle events:

- **`addObserver(LifecycleObserver observer)`**: Registers an observer to receive lifecycle events.
- **`removeObserver(LifecycleObserver observer)`**: Unregisters an observer.

### LifecycleOwner Interface

The `LifecycleOwner` interface represents a component that has a lifecycle. This interface is implemented
by components that have a lifecycle, such as `Activity` and `Fragment`.

The `LifecycleOwner` interface defines a method to get the `Lifecycle` object associated with the
component:

- **`getLifecycle()`**: Returns the `Lifecycle` object associated with the component.

### Usage Example

Here’s an example of how you might use `Lifecycle` and `LifecycleOwner` in an `Activity`:

1. **Implement LifecycleOwner**:
- An `Activity` implements the `LifecycleOwner` interface.

```java
import androidx.appcompat.app.AppCompatActivity;
import androidx.lifecycle.Lifecycle;
import androidx.lifecycle.LifecycleObserver;
import androidx.lifecycle.OnLifecycleEvent;
import androidx.lifecycle.ViewModelProvider;

public class MainActivity extends AppCompatActivity {

    private MyViewModel viewModel;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        viewModel = new ViewModelProvider(this).get(MyViewModel.class);

        // Add a lifecycle observer
        getLifecycle().addObserver(new LifecycleObserver() {
            @OnLifecycleEvent(Lifecycle.Event.ON_RESUME)
            public void onResume() {
                // Handle onResume event
            }

            @OnLifecycleEvent(Lifecycle.Event.ON_PAUSE)
            public void onPause() {
                // Handle onPause event
            }
        });
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();
        // Remove observers if necessary
        getLifecycle().removeObserver(lifecycleObserver);
    }
}
```

2. **Define Lifecycle Events**:
- You can define methods to handle specific lifecycle events using the `@OnLifecycleEvent` annotation.

```java
public class MyViewModel extends ViewModel {

    public void doSomething() {
        // Perform some action
    }

    public void doSomethingElse() {
        // Perform another action
    }
}
```

### Summary

- **Lifecycle Interface**: Represents the lifecycle of a component and provides methods to observe
lifecycle events.
- **LifecycleOwner Interface**: Represents a component that has a lifecycle and provides a method to get
the `Lifecycle` object.

By using these interfaces, you can manage the lifecycle of components more effectively, ensuring that
resources are properly released and data is not lost during configuration changes.

In the provided code, `MainActivity` implements the `LifecycleOwner` interface by extending
`AppCompatActivity`, which already implements `LifecycleOwner`. Therefore, `MainActivity` already has
access to the `Lifecycle` object and can use it to add and remove lifecycle observers.

Here's a breakdown of the key parts of the code:

1. **Extending AppCompatActivity**:
```java
public class MainActivity extends AppCompatActivity {
   ```
By extending `AppCompatActivity`, `MainActivity` inherits the `LifecycleOwner` interface.

2. **Getting the Lifecycle Object**:
```java
getLifecycle()
   ```
This method call retrieves the `Lifecycle` object associated with `MainActivity`.

3. **Adding Lifecycle Observers**:
```java
getLifecycle().addObserver(new LifecycleObserver() {
    @OnLifecycleEvent(Lifecycle.Event.ON_RESUME)
    public void onResume() {
        // Handle onResume event
    }

    @OnLifecycleEvent(Lifecycle.Event.ON_PAUSE)
    public void onPause() {
        // Handle onPause event
    }
});
   ```
This code adds a `LifecycleObserver` to the `Lifecycle` object. The observer listens for `ON_RESUME`
and `ON_PAUSE` events, allowing you to handle these lifecycle events within the observer.

4. **Removing Lifecycle Observers**:
```java
getLifecycle().removeObserver(lifecycleObserver);
   ```
This code removes an observer from the `Lifecycle` object. Note that in the provided code,
`lifecycleObserver` is not defined. It should be an instance of a class that implements
`LifecycleObserver`.

### Example with a Defined Observer

To complete the example, you need to define an `Observer` class that implements `LifecycleObserver`:

```java
import androidx.lifecycle.LifecycleObserver;
import androidx.lifecycle.OnLifecycleEvent;

public class MyLifecycleObserver implements LifecycleObserver {

    @OnLifecycleEvent(Lifecycle.Event.ON_RESUME)
    public void onResume() {
        // Handle onResume event
    }

    @OnLifecycleEvent(Lifecycle.Event.ON_PAUSE)
    public void onPause() {
        // Handle onPause event
    }
}
```

Then, you can use this observer in your `MainActivity`:

```java
import androidx.appcompat.app.AppCompatActivity;
import androidx.lifecycle.Lifecycle;
import androidx.lifecycle.ViewModelProvider;

public class MainActivity extends AppCompatActivity {

    private MyViewModel viewModel;
    private MyLifecycleObserver lifecycleObserver;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        viewModel = new ViewModelProvider(this).get(MyViewModel.class);

        lifecycleObserver = new MyLifecycleObserver();
        getLifecycle().addObserver(lifecycleObserver);
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();
        getLifecycle().removeObserver(lifecycleObserver);
    }
}
```

In this example, `MyLifecycleObserver` is a class that implements `LifecycleObserver` and handles
`ON_RESUME` and `ON_PAUSE` events. The observer is created in `MainActivity` and added to the `Lifecycle`
object in `onCreate`. It is also removed from the `Lifecycle` object in `onDestroy`.

## Lifecycle State

`Lifecycle.State` is an enum in the AndroidX Lifecycle library that represents the current state of a
`Lifecycle` object. The `Lifecycle.State` enum includes the following states:

- `DESTROYED`
- `INITIALIZED`
- `CREATED`
- `STARTED`
- `RESUMED`

Understanding and using these states is essential for observing and responding to changes in the
lifecycle of components like `Activity`, `Fragment`, and `ViewModel`. Here’s how you can use
`Lifecycle.State`:

### Adding a LifecycleObserver with State Filtering

You can add a `LifecycleObserver` to a `Lifecycle` object and specify which states it should observe.
This allows you to react to specific lifecycle transitions.

#### Example: Observing States

```java
import androidx.lifecycle.Lifecycle;
import androidx.lifecycle.LifecycleObserver;
import androidx.lifecycle.OnLifecycleEvent;

public class MyLifecycleObserver implements LifecycleObserver {

    @OnLifecycleEvent(Lifecycle.Event.ON_CREATE)
    public void onCreate() {
        System.out.println("LifecycleEvent: ON_CREATE");
    }

    @OnLifecycleEvent(Lifecycle.Event.ON_START)
    public void onStart() {
        System.out.println("LifecycleEvent: ON_START");
    }

    @OnLifecycleEvent(Lifecycle.Event.ON_RESUME)
    public void onResume() {
        System.out.println("LifecycleEvent: ON_RESUME");
    }

    @OnLifecycleEvent(Lifecycle.Event.ON_PAUSE)
    public void onPause() {
        System.out.println("LifecycleEvent: ON_PAUSE");
    }

    @OnLifecycleEvent(Lifecycle.Event.ON_STOP)
    public void onStop() {
        System.out.println("LifecycleEvent: ON_STOP");
    }

    @OnLifecycleEvent(Lifecycle.Event.ON_DESTROY)
    public void onDestroy() {
        System.out.println("LifecycleEvent: ON_DESTROY");
    }
}
```

#### Adding the Observer

```java
import androidx.lifecycle.Lifecycle;
import androidx.lifecycle.LifecycleOwner;

public class MyLifecycleOwner implements LifecycleOwner {
    private Lifecycle lifecycle;

    public MyLifecycleOwner() {
        this.lifecycle = new Lifecycle(this);
    }

    @Override
    public Lifecycle getLifecycle() {
        return lifecycle;
    }

    public void addLifecycleObserver(Object observer) {
        lifecycle.addObserver(observer);
    }
}
```

### Summary

Using `Lifecycle.State` allows you to observe and respond to specific lifecycle events and states. This
can help you manage resources more effectively and ensure that your components behave correctly at
different points in their lifecycle. By adding a `LifecycleObserver` and specifying which states to
observe, you can achieve a more decoupled and modular codebase.

## Lifecycle hooks vs Lifecycle Observers

Using lifecycle hooks and adding a `LifecycleObserver` are both valid approaches for handling lifecycle
events in Android, and each has its own use cases and benefits. Here’s a detailed comparison to help you
decide when to use each approach:

### Using Lifecycle Hooks

#### Lifecycle Hooks
Lifecycle hooks are methods that are automatically called by the system when the lifecycle state of an
activity or fragment changes. Common lifecycle hooks include `onResume()`, `onPause()`, `onStart()`,
`onStop()`, etc.

**Example:**
```java
@Override
protected void onResume() {
    super.onResume();
    // Handle onResume event
}

@Override
protected void onPause() {
    super.onPause();
    // Handle onPause event
}
```

#### Advantages of Lifecycle Hooks
1. **Simplicity**: Lifecycle hooks are straightforward and easy to use. They are directly tied to the
lifecycle events, making the code easy to understand and maintain.
2. **IntelliSense**: IDEs provide good support for lifecycle hooks, such as code completion and
navigation, making it easier to work with them.
3. **Direct Access to Context**: Lifecycle hooks provide direct access to the activity or fragment
context, which can be useful for managing resources and performing operations that require the context.

#### Disadvantages of Lifecycle Hooks
1. **Limited Flexibility**: Lifecycle hooks are tied to the specific lifecycle events and cannot be used
to observe other types of lifecycle events (e.g., changes in the lifecycle of a ViewModel).
2. **Potential for Code Duplication**: If you need to handle the same lifecycle event in multiple
activities or fragments, you might end up duplicating code.

### Using LifecycleObserver

#### LifecycleObserver
A `LifecycleObserver` is an interface that allows you to observe lifecycle events without directly
implementing them in your activity or fragment. You can add an observer to a `Lifecycle` object and
define methods annotated with `@OnLifecycleEvent`.

**Example:**
```java
getLifecycle().addObserver(new LifecycleObserver() {
    @OnLifecycleEvent(Lifecycle.Event.ON_RESUME)
    public void onResume() {
        // Handle onResume event
    }

    @OnLifecycleEvent(Lifecycle.Event.ON_PAUSE)
    public void onPause() {
        // Handle onPause event
    }
});
```

#### Advantages of LifecycleObserver
1. **Flexibility**: `LifecycleObserver` allows you to observe lifecycle events from anywhere in your
application, not just in activities or fragments. This can be useful for decoupling concerns and making
your code more modular.
2. **Shared Observers**: You can create a single `LifecycleObserver` class and use it across multiple
activities or fragments, reducing code duplication.
3. **Testability**: `LifecycleObserver` makes it easier to write unit tests for components that depend on
lifecycle events, as you can easily inject mock lifecycle objects.

#### Disadvantages of LifecycleObserver
1. **Complexity**: `LifecycleObserver` requires more boilerplate code to set up and manage observers. It
might be more difficult to understand at first, especially for developers new to the concept.
2. **Less Intuitive**: Lifecycle hooks are more intuitive for developers familiar with Android's
lifecycle model, as they directly correspond to lifecycle events.
3. **No Direct Context Access**: `LifecycleObserver` does not provide direct access to the context, which
might be necessary for some operations.

### When to Use Each Approach

- **Use Lifecycle Hooks**:
  - When you need to handle lifecycle events directly within your activity or fragment.
  - When you want to keep your code simple and straightforward.
  - When you need to access the context directly in your lifecycle event handling.

- **Use LifecycleObserver**:
  - When you need to observe lifecycle events from anywhere in your application.
  - When you want to decouple your components and make your code more modular.
  - When you need to write unit tests for components that depend on lifecycle events.

In summary, both approaches have their merits, and the choice between them depends on the specific needs
of your application. If simplicity and direct access to the context are priorities, lifecycle hooks might
be the better choice. If flexibility, modularity, and testability are more important, `LifecycleObserver`
might be a better fit.
